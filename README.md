# WellMind Assistant

**A conversational mental health information assistant. It uses RAPTOR-based Retrieval-Augmented Generation (RAG) over trusted NIMH publications, built with LangChain, FAISS, Groq, and Streamlit.**

## Overview

WellMind Assistant answers questions about mental health topics such as anxiety, depression, ADHD, PTSD, bipolar disorder, eating disorders, and suicide prevention. Its answers are grounded in a curated set of public-domain publications from the **National Institute of Mental Health (NIMH)**.

Basic RAG splits documents into flat chunks. WellMind Assistant uses **RAPTOR** (Recursive Abstractive Processing for Tree-Organized Retrieval) instead: it clusters document content and summarizes it recursively, building a multi-level knowledge tree. That lets the assistant answer both detailed questions and broad, high-level ones.

---

## Key Features

- **RAPTOR retrieval.** A multi-level tree of document summaries, built with UMAP and Gaussian Mixture Model clustering, helps the assistant answer both specific and high-level questions.
- **Conversational memory.** A history-aware retriever turns follow-up questions ("what are its symptoms?") into standalone queries, so multi-turn conversations stay coherent.
- **Trusted knowledge base.** Built from NIMH publications covering 20+ mental health topics.
- **Fast inference.** Answers are generated by LLMs served on **Groq**. Azure OpenAI is supported as an alternative provider.
- **Local vector search.** A precomputed FAISS index with `BAAI/bge-small-en-v1.5` embeddings runs on the CPU, with no GPU required.
- **Grounded answers.** The assistant says "I don't know" instead of guessing when the context doesn't cover a question.
- **Simple chat UI.** A clean Streamlit chat interface.
- **Observability.** LangSmith tracing is built in for inspecting chains and retrieval.

## Getting Started

### Prerequisites

- **Python 3.10+**
- A **Groq API key** (free at [console.groq.com](https://console.groq.com))
- *(Optional)* An Azure OpenAI deployment
- *(Optional)* A LangSmith API key for tracing

### 1. Clone the repository

```bash
git clone https://github.com/zaynnmotiwala/wellmind-assistant.git
cd wellmind-assistant
```

### 2. Create a virtual environment and install dependencies

```bash
python -m venv venv
venv\Scripts\activate          # macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
```

### 3. Configure secrets

The app reads model settings from Streamlit secrets. Create `.streamlit/secrets.toml`:

```toml
# Required: Groq (default LLM provider)
GROQ_API_KEY = "your_groq_api_key"
GROQ_MODEL_NAME = "llama-3.1-8b-instant"

# Embeddings
EMBEDDING_MODEL_NAME = "BAAI/bge-small-en-v1.5"

# Optional: Azure OpenAI (alternative provider)
AZURE_OAI_KEY = "your_azure_openai_key"
AZURE_OPENAI_ENDPOINT = "https://your-resource.openai.azure.com/"
AZURE_OPENAI_DEPLOYMENT = "your_deployment_name"
AZURE_OPENAI_API_VERSION = "2024-08-01-preview"
```

For LangSmith tracing (enabled by default in `app.py`), create a `.env` file:

```env
LANGCHAIN_API_KEY=your_langsmith_api_key
```

> Never commit `.env` or `.streamlit/secrets.toml`. Add both to `.gitignore`.

### 4. Run the app

```bash
streamlit run app.py
```

The app opens at **http://localhost:8501**.

## Rebuilding the Knowledge Base (Optional)

A prebuilt FAISS index ships in `faiss_db_raptor/`, so you can skip this step. To rebuild it with your own documents:

1. Put your PDF files in a `data/` folder (subfolders are supported).
2. Run the indexing script:

   ```bash
   cd mental_healthcare_chatbot
   python vector_saver.py
   ```

The script loads the PDFs, builds a 3-level RAPTOR summary tree, and saves the leaf texts and summaries to `faiss_db_raptor/`.

> Indexing makes many LLM calls to summarize the clusters, so it can take a while and uses API quota.

## How It Works

1. **Load.** NIMH PDFs are loaded page by page.
2. **Cluster.** Page embeddings are reduced with UMAP and grouped with Gaussian Mixture Models, using BIC to pick the number of clusters.
3. **Summarize.** The LLM summarizes each cluster. The summaries are embedded and clustered again, for up to 3 levels.
4. **Index.** The original pages and all summaries go into a single FAISS index.
5. **Rewrite.** At query time, the user's question is rewritten into a standalone question using the chat history.
6. **Retrieve.** FAISS returns the most relevant pages and summaries.
7. **Answer.** The LLM writes an answer grounded only in the retrieved context.

## Limitations

- **Not medical advice.** Answers are informational and may be incomplete. Always consult a qualified professional.
- **Fixed knowledge base.** The assistant only knows what is in the indexed documents.
- **Session-only memory.** Chat history lives in the Streamlit session and is lost on refresh.
- **No crisis detection.** The app does not detect emergencies or escalate them.
